# web

Сайт на Next.js 16 (App Router, React 19, Cache Components, React Compiler), стили на SCSS.

## Команды

Проверки запускаются из корня репозитория (`npm run verify`). В этой папке:

```bash
npm run dev         # dev-сервер на http://localhost:3001
npm run build       # production-сборка (.next/standalone)
npm run start       # запуск собранного сервера на порту 3001
npm run typecheck   # типы маршрутов (next typegen) и проверка TypeScript
npm test            # тесты Vitest (jsdom, Testing Library): src/**/*.test.ts(x), Docker не нужен
```

Сборка не обращается к api, Redis и базе: данные с api рендерятся при запросе внутри `<Suspense>`,
а при сборке пререндерится только статичная оболочка страницы.

## Структура

`app/` содержит только маршрутизацию: каждый `page.tsx` реэкспортирует страницу из `src/_pages`.
Весь остальной код лежит в `src/` по слоям Feature-Sliced Design, импорт `@/…` указывает на `src/`.

Слои сверху вниз. **Слой импортирует только из слоёв ниже себя**, никогда вверх и никогда из
соседнего среза своего же слоя:

| Слой       | Что в нём                                                                                        | Импортирует из                               |
| ---------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| `_app`     | глобальная настройка: провайдеры (TanStack Query, состояние интерфейса), глобальные стили        | всех слоёв ниже                              |
| `_pages`   | страницы целиком                                                                                 | `widgets`, `features`, `entities`, `shared`  |
| `widgets`  | крупные самостоятельные блоки страницы: шапка, лента товаров, блок примерки                      | `features`, `entities`, `shared`             |
| `features` | действия пользователя: загрузить фото, выбрать размер, запустить примерку                        | `entities`, `shared`                         |
| `entities` | бизнес-сущности: типы, запросы к api (хуки TanStack Query и ключи запросов), простое отображение | `shared`                                     |
| `shared`   | переиспользуемое без знания о бизнесе: клиент api, конфигурация, ui-компоненты, утилиты          | только из своих сегментов (`api` → `config`) |

Каждый срез (`_pages/home`, `entities/product`, …) отдаёт наружу только то, что экспортирует его
`index.ts`; внутренние файлы среза снаружи не импортируются. Данные с сервера живут в `entities`
(TanStack Query), а не в хранилище состояния интерфейса.

Префикс `_` у `_app` и `_pages` нужен, чтобы имена не путались с папками `app/` и `pages/`, которые
Next.js трактует как маршруты. Пустые слои держатся в git файлом `.gitkeep`, пока в них нет кода.

## UI-kit

Внешний вид повторяет Lamoda (спека 0003): цвета, размеры, отступы и состояния взяты из её стилей,
логотипа и шрифтов Lamoda нет.

- **Токены** — `src/shared/styles/tokens.scss`: CSS custom properties для цветов, типографики,
  радиусов, теней, отступов (шаг 4px) и длительности анимаций. Файл подключается один раз в
  `app/globals.scss`; стили компонентов читают значения только через `var(--…)`, своих цветов и
  размеров не держат. Тема одна, светлая; тёмную можно добавить, переопределив те же свойства.
  При `prefers-reduced-motion` длительности анимаций равны нулю.
- **Шрифт** — Onest через `next/font/google` в `app/layout.tsx`. Next скачивает его при сборке и
  отдаёт с нашего домена, браузер к Google не обращается. Переменная шрифта (`--font-onest`) стоит
  на `<html>`, токен `--font-sans` ссылается на неё.
- **Компоненты** — `src/shared/ui/<компонент>/`: свой `.tsx`, свой `.module.scss` и тест, если есть
  логика; наружу всё отдаёт `src/shared/ui/index.ts`. Поведение (фокус, клавиатура, ARIA) берётся
  из Base UI (`@base-ui/react`): его части обёрнуты в наши компоненты и стилизуются через
  `className` и атрибуты состояния `data-*` (`data-disabled` и другие). Остальной код импортирует
  только `@/shared/ui`, не `@base-ui/react`.
- **Кнопки и ссылки** — `Button` (`primary`, `secondary`, `outline`; высота 32–56px; `loading`
  показывает `Spinner`, ставит `aria-busy` и оставляет кнопку в фокусе), с `href` — ссылка в виде
  кнопки (`next/link`, без Base UI: ссылке не дают роль кнопки). `IconButton` — квадратная кнопка с
  одной иконкой, `aria-label` обязателен. `Link` — текстовая ссылка на `next/link`.
- **Поля** — `TextField`: поле Lamoda высотой 56px с нижней границей и «плавающей» подписью
  (`label`), под ним подсказка `hint` или ошибка `error` (ошибка ставит `aria-invalid`; подпись,
  подсказка и ошибка связаны с полем через Base UI `Field`). `SearchField` — форма `role="search"`:
  серое поле, крестик «Очистить», пока поле заполнено, и чёрная кнопка «Найти»; Enter или кнопка
  вызывают `onSearch` с обрезанным по краям запросом, пустой запрос не отправляется.
- **Выбор** — `Checkbox` (квадрат 14px), `Radio` (круг 20px) и `Switch` (дорожка 34×14 с бегунком
  20px); текст подписи передаётся как `children` и становится доступным именем, вся строка
  кликабельна. `CheckboxGroup` (значение — массив `value` отмеченных) и `RadioGroup` (одно значение,
  стрелки двигают выбор) требуют `aria-label` или `aria-labelledby`. `Radio` живёт только внутри
  `RadioGroup`. Состояний ошибки и «частично выбрано» нет (D7e спеки 0003).
- **Фильтры** — `FilterDropdown`: чип высотой 36px и выпадающий список под ним (Base UI
  `Popover`, слой `--z-popover`). Enter, пробел или клик открывают список и переносят в него
  фокус, Esc или клик снаружи закрывают и возвращают фокус на чип. Применённый чип чёрный, после
  названия идёт значение (`value`), а с `onClear` в конце стоит отдельная кнопка ×. Содержимое
  списка: `CheckboxFilter` (флажки со счётчиками, поиск `searchable`, «Применить»; отмеченное до
  «Применить» — черновик, который теряется при закрытии), `SortFilter` (радиокнопки применяются
  сразу; клик, пробел или Enter закрывают список, а со стрелками он остаётся открытым, D7f) и
  `PriceFilter` (слайдер с двумя бегунками, поля «Мин. цена» и «Макс. цена» и «Применить»,
  неактивная, пока диапазон не изменился; поле на границе пустое и показывает её серым, D7i;
  введённая цена сразу ставит бегунок туда, куда её поправят: за границей — на границу, за
  другим бегунком — на него; текст поля поправляется при уходе из него или Enter, D7j).
  Список шириной не меньше 292px (D7g). `FilterChip` — чип-переключатель без стрелки
  («Только со скидкой», `aria-pressed`). `FilterChips` — ряд чипов с переносом; с `onClearAll`
  в конце появляется кнопка «Очистить фильтры».
- **Размеры и цвета** — `SizePicker`: размеры фильтра, ячейки 46×46, можно выбрать несколько
  (флажки Base UI, значение — массив, D7m). `SizeSelector`: размеры товара, ячейки 56×52, выбран
  один (радиогруппа, стрелки двигают выбор). Размер `soldOut` серый с диагональю: скринридер
  называет его недоступным (`aria-disabled`), клик его не выбирает, стрелки его пропускают (D7n).
  `ColorSwatch` — строка фильтра цвета внутри `CheckboxGroup`: круг 18px цвета из палитры Lamoda
  (`color`, токены `--color-swatch-*`), название и счётчик `count`; галочка белая, на светлых
  цветах чёрная (D7o).
- **Выпадающий список** — `Select`: поле Lamoda с карточки товара (рамка `#888`, значение 16px,
  шеврон), у пунктов может быть миниатюра 23×32 (`thumbnail`, через `next/image`). Base UI
  `Select`: Enter, пробел или клик открывают список, стрелки двигают выделение, Enter выбирает,
  Esc закрывает и возвращает фокус на поле. Список во всю ширину поля, под ним, не выше 216px,
  страница при этом прокручивается (D7p). `placeholder` — серый текст, пока ничего не выбрано;
  требуется `aria-label` или `aria-labelledby`.
- **Товар и заказ** — `Price`: цена через `formatPrice`, со скидкой перед ней одна или две
  зачёркнутые старые цены без «₽», а сама цена красная; `variant` `catalog` (старые 13px, цена
  16px жирная) или `product` (всё 16px). Скринридер слышит «Старая цена …, цена …» (скрытые
  слова, D7r). `Badges` — ряд скошенных плашек Lamoda (`discount`, `club`, `premium`, `promo`),
  одна плашка — ряд из одной; `size` `s` (16px) или `l` (24px). `Rating` — звезда и значение
  «4.7», для скринридера одна картинка «Рейтинг 4,7 из 5»; без `value` ничего не показывает
  (D7s). `FavoriteToggle` — сердечко на Base UI `Toggle` (`aria-pressed`, имя всегда
  «В избранное»): нажатое чёрное и один раз «бьётся», размеры 24, 32 (на фото: белое с серым
  контуром), 48 и 56 (квадрат с рамкой) (D7t). `OrderStatus` — статус заказа 20px цветом тона
  (`primary`, `success`, `warning`, `caution`, `secondary`) и серая дата; дату текстом пишет
  страница (D7u).
- **Навигация** — `Tabs` (Base UI `Tabs`, пункты `items` с панелями): серые подписи, активная
  чёрная с подчёркиванием 2px, размеры `l`, `m`, `s`, счётчик `count` («Отзывы 54»); стрелки,
  Home и End сразу показывают панель; на отключённой (`disabled`) вкладке стрелки
  останавливаются, но её панель не показывается; Tab ведёт в панель (D7v). `Breadcrumbs` — `<nav>` со списком серых ссылок 13px через «/», последний пункт —
  текст с `aria-current="page"`, на узком экране переносятся (D7w). `Pagination` — ссылки
  (`getHref`) или кнопки (`onPageChange`): номера с текущей на сером, «…» вместо далёких страниц,
  «← Назад» и «Дальше →» не показываются на первой и последней, справа «10 из 11» (показано из
  всего, `shown` и `total`), сверху «Показать ещё» при `onShowMore` (D7x). Не клиентский
  компонент, поэтому серверная страница может передать `getHref`. `Accordion` (Base UI
  `Accordion`): строки с шевроном и линией под каждой, открыта одна (или несколько с
  `multiple`), панель раскрывается по высоте, закрытые находит поиск по странице (D7y).
- **Окна и подсказки** — `Modal` (Base UI `Dialog`): белая рамка посреди затемнения, заголовок
  24/28 (имя окна), `description`, содержимое (прокручивается, если не помещается) и кнопки
  `footer` справа; белый × снаружи рамки, как у Lamoda (D7ab). `Drawer` (Base UI `Drawer`):
  шторка справа во всю высоту, 432px или 636px с `wide`, × внутри, на касание закрывается и
  свайпом вправо. У обоих `trigger` — кнопка, которая открывает (или `open`/`onOpenChange`);
  фокус уходит внутрь и не выходит, страница не прокручивается, Esc, клик по затемнению или ×
  закрывают, фокус возвращается на кнопку. Кнопка в `footer`, которая только закрывает, —
  внутри `ModalClose` / `DrawerClose`. Слой — `--z-modal` (ниже `--z-popover`, чтобы список
  внутри окна был поверх него). `Tooltip` (Base UI `Tooltip`, слой `--z-tooltip`): короткая
  подпись к кнопке-иконке для мыши и клавиатуры — через 600 мс наведения или сразу по фокусу с
  клавиатуры, Esc закрывает; скринридер её не слышит, у кнопки свой такой же `aria-label`.
  `HelpTip` — «?» Lamoda (круг 14px) с той же белой подсказкой на Base UI `Popover`: открывают
  наведение, клик, касание, Enter или пробел, скринридер читает её текст (D7aa). На странице
  всё это открывается только вживую (D7z).
- **Иконки** — `src/shared/ui/icon/`: по компоненту на иконку (`ChevronDownIcon`, `HeartIcon`, …),
  размер `size` 16 или 24 (по умолчанию 24), цвет `currentColor`. Без `title` иконка декоративная
  (`aria-hidden`); иконке, которая стоит отдельно без текста рядом, передаётся `title`, он становится
  её доступным именем. Кнопка из одной иконки — `IconButton` с обязательным `aria-label`, иконка в
  ней без `title`. Рисунок для каждого размера свой; где он один, второй размер получается
  масштабированием: обводка остаётся толщиной 1px, а у `MapPinIcon` (нарисован заливкой) линии на
  16px тоньше, около 0,7px.
- **Страница `/ui-kit`** — срез `src/_pages/ui-kit`, маршрут `app/ui-kit/page.tsx`. Показывает токены
  и каждый компонент во всех состояниях. Список разделов один, `ui/sections.ts`: из него
  строятся и оглавление, и разделы, поэтому новый компонент добавляется туда. Значения, которые
  раздел токенов подписывает под образцами, лежат в `config/tokens.ts` и должны совпадать с
  `tokens.scss`. Страница открыта в production, но закрыта от поисковиков (`noindex, nofollow`), и
  статична: собирается без api.
